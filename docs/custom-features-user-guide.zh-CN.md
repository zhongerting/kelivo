# Kelivo 个人修改版功能使用手册

核对日期：2026-09-08。依据本地 Kelivo 源码及已记录的交付工作编写。手机已安装 APK 是否包含全部功能，取决于安装包构建时间；本手册不表示已重新构建或安装 APK。

## 1. 先安装行动选项世界书

文件：`samples/kelivo-rp-action-options-world-book.json`。

1. 把 JSON 文件传到手机的下载目录。
2. 在 Kelivo 的“设置 → 世界书”中使用导入操作，选择该文件。
3. 确认出现“Kelivo RP 行动选项”，其中只有一条“行动选项生成规则（常驻）”；世界书和条目均需启用。
4. 切到要使用的助手，在聊天输入区的世界书选择入口中选中此书。仅导入到管理列表不等于已为助手激活。
5. 关闭原生“聊天建议”的生成开关，避免另一次建议请求。
6. 发送一条正常的剧情续写请求。正文先流式显示，整条回复结束后，输入框上方出现行动选项栏。

此文件是可导入的数据文件，没有自动写入手机应用数据库，也没有自动内置进现有 APK。重复导入可能产生多份同名世界书，保留一份启用即可。

默认规则：2～6 个选项、用户角色第一人称、通常每项不超过 40 字、方向不同、不预先决定结果、不泄露角色未知信息。以作者身份写作时，生成续写方向。可以直接编辑条目正文修改这些规则。固定的 `<kelivo_options>`、`<option>` 及闭合标记必须保持不变。

若没有选项：依次检查是否使用支持行动选项的 APK、世界书是否为当前助手激活、条目是否常驻启用、模型是否完整结束回复，以及其他预设是否要求“只能输出正文”或另一套末尾格式。模型没有按格式输出时，程序不会额外调用模型补生成。

## 2. 聊天主界面管理指令注入

用途：保存反复使用的写作规则，例如“保持第三人称”“本轮重点描写对话”“继续下一章”。我们增加了从聊天界面打开并管理卡片的便捷流程。

使用步骤：

1. 在聊天输入区工具菜单中打开“指令注入”。
2. 使用添加操作创建卡片，填写名称和提示词；已有卡片可以编辑或删除。
3. 选择需要启用的卡片，再正常发送消息。启用内容会加入模型请求的系统提示部分。
4. 不再需要的规则取消启用；要永久移除才删除卡片。

作用范围：当前代码按助手保存激活卡片列表，并可继承默认列表。同一助手的其他对话可能使用同一组规则，并非每个 conversation 独有。管理卡片内容也会影响使用该卡片的其他地方。

与助手系统提示词的区别：系统提示词适合稳定规则，注入卡片适合便捷切换的附加规则。二者都会进入请求，矛盾要求可能干扰模型。修改注入设置不会重写已经生成的回复。

## 3. 快捷回复的“发送”和“追加”

用途：快速输入固定短语，例如“继续”“继续下一章”。固定快捷短语无需模型生成，和动态行动选项是两个功能。

打开聊天输入区的快捷短语菜单后：

- 点击短语本身：直接通过正常聊天流程发送这段文字。
- 点击右侧“追加”：在输入框光标处插入；存在选区时替换选中文字；不发送，并把焦点返回输入框。

直接发送会保留输入框原草稿和附件，附件不会随这次短语一起发送。需要把附件与短语一起发出时，先“追加”，然后使用输入框发送按钮。移动端和桌面端语义一致。

## 4. 动态 RP 行动选项

用途：让主模型结合剧情给出下一步行动，点击即可继续故事。生成要求由世界书或预设提供，程序负责解析和展示。

正文和选项共用同一次主聊天请求，使用同一套有效输入，包括实际进入请求的系统提示、角色设定、预设、世界书和历史。有效输入仍受上下文裁剪及过滤设置影响。

交互：

- 正文正常流式显示；选项在回复完整结束并解析成功后一次性出现。
- 最多显示六个去重后的非空选项。
- 点击选项文本直接发送该行动，保留原草稿和附件。
- 点击“追加”只插入到输入框，选项仍可继续使用。
- 右侧箭头展开或收起，应用记住上次状态。
- 选项绑定具体助手、对话和回复版本。面板从当前选中版本链的最后一条完整助手消息读取，不是再次拿最后一条消息请求模型。
- 发送期间、对话或助手切换期间隐藏；切换结束后是否出现取决于目标对话末条消息是否有匹配选项。

选项作为独立消息部分保存，后续正常聊天历史的正文不包含选项列表。你点击发出的那条行动会作为真实 user 消息进入后续历史。界面隐藏选项不等于删除持久化选项。

原生聊天建议仍是独立功能：它会额外请求模型，默认读取最近最多 8 条消息、最多 4000 字符。从 1.2.6+74 起最多保留和显示七项建议，默认提示词仍要求三项；可自定义提示词要求六至七项。当前代码没有自动互斥开关，使用正文内行动选项时请自行关闭原生聊天建议；改用原生建议时则启用聊天建议并停用行动选项世界书。

## 5. 导入 SillyTavern 世界书

用途：复用现有世界设定、地点、人物知识或常驻提示规则。世界书机制本身来自 Kelivo，我们扩展了 SillyTavern JSON 格式导入。

1. 打开“设置 → 世界书”，导入 JSON。
2. 阅读导入报告，检查转换、跳过及不支持项。
3. 展开条目，核对正文、关键词、常驻状态、启用状态和注入位置。
4. 在目标助手的聊天世界书选择入口中激活需要的书。

关键词条目需匹配扫描范围内的文本才触发；常驻条目无需关键词匹配，但仍需书和条目被启用。格式可导入不代表 SillyTavern 所有高级触发语义都能完全复现。

独立世界书导入与角色卡内嵌世界书转换策略有区别。内嵌书更保守：无法准确表达的高级条件或纯正则条目默认禁用，混合关键词条目可能只保留普通关键词。请先检查警告，确认含义后再手动启用。

## 6. SillyTavern 提示词预设

用途：把一份大型预设拆成可逐项开关的提示词内容，避免全部挤在一个系统提示框。

1. 打开“设置 → 提示词预设”，导入 JSON。
2. 阅读报告，展开预设检查各条目，按需要启用、停用和编辑。
3. 打开目标助手的编辑页面，在“提示词”页的“提示词预设”选择器中选择一份预设。
4. 正常聊天。更换或取消预设仍使用同一选择器。

每个助手同时选择一份预设；多个助手使用同一份预设时，编辑共享预设会影响它们。保留受支持提示词的 system/user/assistant 角色和顺序，但这是提示词内容兼容，不是完整酒馆运行时复刻。

模型采样参数、脚本、插件功能不会因为导入预设就自动获得支持。助手系统提示词、人物设定、指令注入和世界书仍可一起生效；重复或冲突要求应手动整理。预设内容中的动态占位符不能一概视为全部支持。

## 7. 角色卡导入与 RP 助手

用途：直接从角色卡创建带人物设定和开场白的助手。

1. 打开助手管理页面，选择“导入角色卡”。
2. 选择 V1/V2/V3 JSON 角色卡或包含 chara/ccv3 元数据的 PNG；普通图片不是角色卡。
3. 核对导入报告与新建助手的名称、头像、人物设定和开场白。
4. 如包含内嵌世界书，检查转换报告及自动绑定结果。
5. 为此助手选择模型和需要的提示词预设，然后创建新对话。

导入字段包括名称、PNG 头像、description/personality/scenario、first_mes 和 character_book。人物设定独立于系统提示词保存；开场白是新对话中的真实 assistant 消息，同一对话不会因重开页面而重复插入。修改开场白后主要通过新建对话观察效果。

未导入的部分包括 system_prompt、post_history_instructions、mes_example、alternate_greetings、depth_prompt、角色卡正则脚本、插件配置及模型参数。依赖这些功能的复杂卡不会完整复现酒馆效果。不要把“成功导入”理解为卡片的所有玩法都能运行。

普通助手继续使用原有聊天方式。RP 助手额外保存人物设定与开场白，但没有内置完整的酒馆脚本运行环境。

## 8. 后续上下文排除历史推理

用途：减少后续请求重复发送已有思考内容的成本，同时保留手机上的思考展示。

在“助手编辑 → 提示词”中找到“从未来上下文中排除历史推理”并开启。之后的新请求使用过滤后的历史正文。已存消息、思考显示、导出和备份保持完整。

处理覆盖普通聊天、上下文压缩、聊天建议、记忆提取及标题生成等路径。当前轮工具续接需要的推理或协议制品，以及 Gemini thoughtSignature 等必要数据会保留；不会为节省 token 破坏协议。

这个开关不会关闭模型本轮思考，也不退回以前已经消耗的 token。没有明确标记、混在普通正文中的思考不能保证被识别。关闭开关后，允许的历史推理可重新进入后续上下文。行动选项的分离存储是另一个机制，不依赖此开关。

## 9. Android 使用体验与版本维护

我们采用 Release APK 交付，解决过 Debug 构建在用户手机上键盘弹出明显卡顿的问题。Release 提升运行性能，但不能保证网络、模型生成或所有大对话操作都没有等待。

修改版包含用户提供的启动图标；Debug 版使用独立应用 ID 和名称，可与 Release 共存，因此两者数据不能当作同一个应用的数据。

官方更新提示默认关闭，避免误装官方包覆盖个人功能；已有明确保存的更新设置可能继续有效。升级个人版本请使用后续提供的修改版 APK，重要数据先备份。能否覆盖安装还取决于签名和版本要求。

Fork 配置过上游跟踪与自动同步工作流，它负责源码同步，不会自动更新手机 APK。遇到合并冲突或验证失败需要处理；不能把一次工作流配置当作所有开发分支始终自动同步的保证。

## 10. 上下文检查与组合使用

Context Logger 可辅助查看一次请求实际包含的提示词来源和长度。排查时重点核对人物设定、预设、指令注入、世界书和聊天历史是否进入本轮请求；调试日志可能包含私人内容，分享前检查。

推荐的小说组合：导入角色卡创建 RP 助手，选择一份写作预设，激活剧情世界书和本次行动选项世界书，开启历史推理过滤，然后新建对话开始。固定的“继续下一章”用快捷短语，临时文风要求用指令注入。

如果发生冲突，先减少同时启用的规则，再逐项恢复。尤其注意要求“只输出正文”“必须以其他标签结尾”的预设可能和行动选项的末尾协议冲突。

## 11. 尚不能视为已交付的功能

小说记忆表格已有总体方案并安排了第一阶段任务，但本次未审计该任务的交付结果，不能当作当前 APK 已可用的功能。角色、事件、关系表自动整理及以摘要替换旧历史，需等待独立验收。

联网搜索、原生用户长期记忆、基础世界书等是 Kelivo 自身能力，不应全部算作我们新增的功能。本手册重点记录修改版扩展和与这些原生功能的配合方式。
