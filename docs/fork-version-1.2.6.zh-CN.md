## 自定义功能及原理

### 聊天指令注入

从聊天界面管理可重复使用的提示词卡片，支持添加、编辑、删除与激活。
卡片通过 InstructionInjectionProvider 按助手选择，消息构建时将启用正文追加到系统提示部分。
它是系统提示的附加内容，可能与原有设定同时生效。激活状态按助手保存，不保证每个对话独立。

### 快捷回复发送与追加

点击短语直接通过正常发送流程发送；右侧“追加”在光标处插入或替换选区。
直接发送只传短语文字，保留输入框已有草稿和附件。追加只修改输入框并恢复焦点。
固定快捷短语不调用模型，与动态剧情选项独立。

### RP 行动选项

世界书或预设要求主聊天模型在正文末尾输出一个固定格式块：

```xml
<kelivo_options>
<option>我询问对方的来意。</option>
<option>我观察附近的动静。</option>
</kelivo_options>
```

正文与选项共用同一次主请求及其全部有效上下文，无需额外生成请求。
流式解析暂扣选项标记及之后内容，完整结束后解析、去重并最多保留六项。
正文与 ReplyOptionsPart 分开保存，选项关联助手、对话及具体回复版本。
输入框上方的面板展示当前末条完整助手回复的选项，记住展开/收起状态。
直接发送保留草稿和附件，追加后保留选项。未来历史正文不包含整个选项列表；实际选中的行动作为 user 消息保留。

关键模块：`lib/core/utils/reply_options_parser.dart`、`reply_options_selector.dart`、
`lib/features/home/widgets/reply_options_panel.dart` 和聊天控制器。
原生聊天建议仍有独立开关，开启时会另发请求；使用本功能建议关闭它。

### SillyTavern 世界书导入

WorldBookImportService 识别 Kelivo 与常见 SillyTavern JSON 形状，转换为本地世界书模型。
保留可表达的关键词、常驻、顺序、启用和注入位置等字段，并报告不支持或跳过的项目。
导入后仍须为目标助手激活。独立导入与角色卡内嵌书使用不同转换策略，后者对高级触发条件采取更保守的禁用策略。

### 提示词预设导入

导入受支持的提示词条目，保留 system/user/assistant 角色及条目顺序，允许手动开关。
每个助手选择一份预设，发送时由消息构建器插入所选内容。
这不是完整 SillyTavern 运行环境；采样配置、插件脚本和所有动态宏不因此自动受支持。

### 角色卡与 RP 助手

支持 JSON V1/V2/V3 和带 chara/ccv3 元数据的 PNG，优先 ccv3。
导入名称、PNG 头像、description/personality/scenario、first_mes 和 character_book。
RP 人物设定独立保存，开场白成为每个新对话唯一的初始 assistant 消息。
内嵌书生成新标识后保存并绑定，导入失败具备回滚处理。
角色卡正则脚本、JS、插件配置、system_prompt、示例对话和备用开场白等不执行或不导入。

### 历史推理过滤

统一的 ModelVisibleHistory 入口为模型构造历史副本，只保留需要的可见正文。
普通聊天、压缩、建议、记忆提取和标题相关路径复用该逻辑。
数据库、界面、导出和备份中的原始思考保留。
当前工具续接与提供商所需签名等协议数据按兼容规则保留，不以简单删除所有字段的方式处理。
本功能减少未来请求重复携带历史推理，不关闭本轮模型推理，也不能保证识别普通正文中未标记的思考。

### 小说 / RP 故事记忆（已有实现，仍需真机长篇验收）

代码包含角色档案、角色状态、关系、事件和情节摘要五类数据，以及 patch、来源摘要和覆盖检查点。
数据由 StoryMemoryRepository 通过现有业务数据库保存，按 conversation 隔离；助手保存开关、整理频率、近期保留量等配置。
后台管线使用记忆模型输出白名单结构化操作，经校验后在 SQLite 事务中写入行数据与检查点。
支持确认流程、来源有效性检查；失败不推进成功覆盖范围。

发送时 StoryMemoryContextBuilder 检查来源版本链，保留近期消息并省略有效覆盖的旧消息副本，加入故事记忆段。
发现来源失效或覆盖空洞时保留原历史并停止该次记忆注入。原消息不会因此被删除。
本次合并还补充了记忆模型请求的 conversationId，跟随上游会话请求头行为。

需要明确的当前限制：

- 注入预算目前按设置值换算字符上限，并非严格按模型真实 token 窗口百分比计算。
- 覆盖检查与最终预算选行是分开的；预算可能省略某些摘要行，不能宣称所有被替代历史的信息必然进入了本次请求。长篇使用需检查实际上下文，后续应加强替代范围与最终注入摘要的绑定。
- 任意模板、向量召回、完整酒馆插件兼容不属于本版已完成能力。
- 聚焦测试通过不等于已完成长期写作质量、真实 API 和真机验收。原使用手册中的“尚未审计交付”描述是早期记录，本节给出当前源码状态。

### Android 自定义与维护

使用用户提供的启动图标；Debug 使用独立应用 ID，可与 Release 共存。
Release 是手机交付模式，避免把 Debug 的运行开销作为性能验收结果。
官方更新提示默认关闭，个人版本更新需安装相应 APK。
Fork 上游同步用于更新源码，不自动更新手机应用，也不保证每个功能分支无冲突同步。
